# 半側空間無視 体験アプリ(教育用 WebXR / Meta Quest)

左半側空間無視の**行動特性の一部**(左への探索・注意・行動選択の低下と右への偏り)を、健常者が教育目的で体験するMVPです。
**患者さんの主観的体験の再現ではありません。半盲(B条件)は比較のための別モデルです。**

- Unity不使用。three.js(r170を`vendor/`に同梱)+素のES Modules。ビルド不要。
- Meta Quest Browser / WebXR Hand Tracking。左右の実手モデルを表示し、机上の物を**つまんで直接**中央の箱へ。

## 起動

### Quest実機(HTTPS必須)
1. **GitHub Pages**(推奨): このフォルダをリポジトリに置いて公開 → QuestブラウザでURLを開き「ENTER VR」。
2. USB接続の開発時: PCで `python3 -m http.server 8000` → `adb reverse tcp:8000 tcp:8000` → Questブラウザで `http://localhost:8000`(localhostは安全なコンテキスト)。
3. Quest設定でハンドトラッキングをON(コントローラーを置いて手を出す)。

### PCプレビュー(ヘッドセット不要)
`python3 -m http.server 8000` → `http://localhost:8000`
マウス=手(押しながら移動でつかむ/離して箱へ)、`Shift`=手を持ち上げ、`A/D`=頭部の左右回旋、`W/S`=上下。ボタンはクリック。

## 流れ
1. メニュー(指でタッチ): **A 通常 / B 半盲(比較) / C Neglect様**
2. 3秒間「まっすぐ前を向く」→ その向きを**身体正中**として机を正面に配置(16物体、左右8個ずつ)
3. 課題「机の上の物をすべて中央の箱へ」。終わったら机奥の「終了」を押す(全部入れると自動終了)
4. **C**: デブリーフ(残存記録 → Neglect効果を解除して通常表示へ戻す → 左の残りに青い輪 → 「左側に○個残っていました」)
5. 「Scanning条件へ」: 同じ課題を**左方向のscanning cue**(左端の青い目印+右→左へ流れる矢印)付きで再実施(Neglect様のsalience低下は同条件のまま、物体配置は入れ替え)
6. 「比較を見る」: Neglect様 と Scanning の左側発見率などを並べて表示

## 条件の実装(`js/salience.js`, `js/scene.js`)
| 条件 | 内容 |
|---|---|
| A | 通常表示 |
| B | 頭部に追従する左視野の遮蔽(黒)。**教育用の比較条件**。物体自体は通常 |
| C | 身体正中基準(頭の向きではない)で、左にある物体ほど コントラスト低下(机色へ最大30%)・彩度低下(最大40%)・hover発光低下(最大70%)。右へ非常に弱い発光パルスを8〜14秒ごとに1回 |
| D | C と同じ + scanning cue |

- 透明化・非表示・左視野の遮蔽は**Cでは一切行わない**(`opacity`/`visible`を触らないことをコードとテストで担保)。
- 頭部を左へ20°以上回旋している間、抑制を徐々に解除(約7秒の持続回旋で解除)。正面へ戻るとゆっくり再抑制。
- 把持半径・ピンチ閾値は左右の手・左右の物体で**同一**(`js/grab.js`, `js/config.js`)。

## ログ(画面上部のボタンでCSV/JSON、VR終了後に取得可能)
- **把持ログCSV** 列: `timestamp, condition, object_id, object_side, object_angle, head_yaw, head_pitch, grab_time, release_time, success, remaining_objects, run_id`
  - 1把持=1行(`head_yaw/pitch`は把持時)。終了時に、未把持・箱の外の物体も `success=0` の行で全て記録。
  - `grab_time/release_time`は課題開始からの秒。`object_angle`は身体正中基準(負=左, 正=右)。
- **頭部ヨーCSV**: 30Hzで `timestamp, run_id, condition, t_run_s, head_yaw, head_pitch`
- **要約JSON**: 各runの左右発見率・最大左/右回旋角・左を最初に探索するまでの時間・注意喚起イベント・物体配置
- 符号規約: `head_yaw` は 負=左, 正=右(校正時の正面=0°)、`head_pitch` は 上=正。

### 指標の定義
- **発見** = 一度でもつかんだ物体。**回収** = 箱に入れた物体。「残存」= 箱に入っていない物体。
- **左を最初に探索するまで** = 課題開始から、頭部が左へ20°以上回旋した最初の時刻(`config.js`の`scan.leftThresholdDeg`)。到達しなければ「未到達」。

## 調整(`js/config.js`)
salienceの強さ、解除速度、注意喚起の頻度、物体配置、把持半径、ピンチ閾値、cueの見た目(`scene.js`)など。

## テスト
`node --test tests/logic.test.mjs`(抑制モデル・解除・配置の左右対称・指標・CSV列)

## 既知の制約(MVP)
- **実機のQuestでは未検証**です(この環境にはヘッドセットがないため)。PCプレビューでUI・把持・ログ・デブリーフの流れは確認済み。実機では、ピンチ閾値(`pinchOn/pinchOff`)、机の高さ(`desk.drop`)、パネルの位置を調整してください。
- 身体正中は「3秒間の頭部の向き」で近似(体幹のトラッキングなし)。回旋中に椅子ごと向きを変えると基準がずれます。
- つかむ操作はピンチのみ(握り込み把持は未実装)。物体は簡易重力落下のみで衝突物理なし。
- 教育用の体験モデルです。診断・評価・治療効果の検証には使えません。1回の体験値で、効果の検証結果ではありません。
- 未実装: 歩行、eye tracking、車椅子、食事課題、音響neglect。
